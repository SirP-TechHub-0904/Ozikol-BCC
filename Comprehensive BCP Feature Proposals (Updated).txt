# Comprehensive BCP Feature Proposals

BCP means **Ozikol Business Command Platform**.

This document reorganizes the platform features into implementation groups. Every major feature should become a dedicated ASP.NET Core Area or a clearly isolated feature module.

Each feature follows the same surface pattern:

```text
Console   = organizational control, staff operations, configuration, reporting, approvals
Workspace = personal user activity, self-service, submissions, personal records
Common    = shared partials, widgets, exports, short links, public screens, reusable routes
```

Very important rule:

```text
Every feature must have its own Console Dashboard.
```

The platform itself also has a main Console dashboard:

```text
/Bcp/Console/Dashboard
```

This main Console dashboard is the first management screen. It oversees billing, active and inactive features, feature setup status, health checks, security, recent visits, reports, recommendations, announcements, and quick actions. The template reference is:

```text
Materialdesignui/console-dashboard.html
```

---

## Route Convention

Recommended route pattern:

```text
/Bcp/Console/Dashboard
/Bcp/Workspace/Dashboard

/Bcp{Feature}/Console/Dashboard
/Bcp{Feature}/Workspace/Dashboard
/Bcp{Feature}/Common/{Resource}
```

Examples:

```text
/BcpTicketing/Console/Dashboard
/BcpTicketing/Workspace/MyTickets
/BcpTicketing/Common/Receipt

/BcpVoting/Console/Dashboard
/BcpVoting/Workspace/Vote
/BcpVoting/Common/PublicResult
```

Some features may also expose short public routes:

```text
/pay/{code}
/f/{code}
/e/{code}
/kb/{module}
```

These public routes should still resolve back to BCP feature services internally.

## Group 1: Platform Core & Governance

These features form the operating foundation of BCP. They should be built before most business modules.

### 1. Platform Console

**Core**
The central command dashboard for the tenant. It gives leadership one place to monitor the entire BCP installation.

**Console**
The first management screen after entering BCP Console mode. It shows active features, inactive features, setup-required features, locked features, current billing, usage, system health, security alerts, recent visits, reports, announcements, and recommendations.

**Workspace**
The personal BCP landing page for a logged-in user. It should summarize personal activities across enabled features: tickets, dues, votes, reports, applications, notifications, and recent activity.

**Common**
Shared navigation, topbar, feature cards, status pills, dashboard widgets, notification widgets, route helpers, and feature catalog UI.

**Dashboard**
Required:

```text
/Bcp/Console/Dashboard
/Bcp/Workspace/Dashboard
```

**Common Routes**

```text
/Bcp/Common/FeatureDirectory
/Bcp/Common/Notifications
/Bcp/Common/Search
```

### 2. Feature Management & Billing

**Core**
Controls which BCP features are available, active, inactive, suspended, locked, or pending setup for a tenant.

**Console**
Tenant owners can activate features, review subscription cost, view invoices, check usage, suspend optional modules, and open setup checklists.

**Workspace**
Normal users do not manage billing, but they may see feature availability messages when a feature is unavailable.

**Common**
Feature status badges, billing widgets, invoice partials, activation prompts, setup checklist partials, usage charts, and subscription notices.

**Dashboard**
Required:

```text
/BcpManagement/Console/Dashboard
```

**Common Routes**

```text
/BcpManagement/Common/SuspendedFeature
/BcpManagement/Common/Invoice
/BcpManagement/Common/FeatureStatus
```

### 3. BCP Identity & Authentication

**Core**
Provides full authentication and account security for BCP. This includes login, logout, registration rules, email confirmation, password reset, password change, two-factor flows, recovery codes, session tracking, trusted devices, lockout, and invitation acceptance.

Because this platform is multi-tenant with separate databases, there should be no `TenantSelect` page inside this area. Tenant/database resolution should happen before or during the authentication pipeline through host, configuration, or deployment context.

**Console**
Security administrators manage identity policy, invitations, login audit, locked accounts, active sessions, password rules, MFA policy, trusted device policy, and authentication risk events.

**Workspace**
Logged-in users manage their own profile security: password, MFA, recovery codes, sessions, trusted devices, login history, email confirmation, and personal security alerts.

**Authenticate**
Unauthenticated users can access only login and recovery flows: login, optional registration, forgot password, reset password, confirm email, resend confirmation, two-factor login, recovery-code login, invite acceptance, access denied, lockout, and session expired.

**Common**
Shared identity UI and helpers: auth status, account menu, security badges, password strength, access-denied panel, lockout panel, session-expired panel, and security notification partials.

**Dashboard**

/BcpIdentity/Console/Dashboard

## Standard Feature Folder Pattern

Every feature should follow this folder shape:

```text
Areas/
  BcpFeatureName/
    Pages/
      Console/
        Dashboard.cshtml
        Dashboard.cshtml.cs
      Workspace/
        Dashboard.cshtml
        Dashboard.cshtml.cs
      Common/
        Partials/
        Exports/
        Receipts/
        Public/
```

The Console dashboard is mandatory for every feature. Workspace dashboards are also recommended for every feature, but may be lightweight when the feature is mostly operational.
